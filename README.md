# ADBMS Assignment 1 — Empirical Investigation of Histograms

## 1. Overview

This project implements and evaluates histogram construction techniques for the PostgreSQL `title` table.

The experiment compares PostgreSQL's built-in histogram statistics with an optimal serial histogram constructed from random samples.

The experiment covers:

- PostgreSQL histograms obtained from `pg_stats`
- Optimal serial (V-optimal / minimum-variance) histograms
- Sample sizes of **1,000**, **3,000**, and **5,000**
- **20 histogram buckets**
- Both `title.id` and `title.title`
- Selectivity-error analysis
- Histogram construction-time analysis
- Three independent trials for every column/sample-size combination
- Averaging of build time and maximum selectivity error over the three trials
- Full-table construction-time extrapolation using linear regression
- Histogram visualizations and sample-size comparison plots
- Row-count and distinct-value validation checks

## 6. `code/histogram.py`

`histogram.py` is the main program for the optimal serial histogram experiment.

### Sampling

For `id`, exactly the requested number of rows is sampled:

```text
1,000
3,000
5,000
```

The sampled values are sorted using PostgreSQL ordering.

For `title`, duplicate rows are retained because duplicate frequencies are required to construct the histogram. The program repeatedly expands the raw sample until it contains exactly the requested number of **distinct title values**.

Therefore, for `title`:

```text
target distinct values = 1,000 / 3,000 / 5,000
```

while the number of raw rows used can be larger than the target because duplicate titles are retained.

### Validation Checks

The program performs explicit checks before constructing the histogram.

For `id`:

```text
requested rows == fetched rows
```

For `title`:

```text
distinct titles == requested target
raw rows >= requested target
```

These checks are performed for every trial.

The program prints the checks to the console and raises an error if a check fails.

### Three Independent Trials

For every sample size, three fresh random samples are generated:

```text
Trial 1
Trial 2
Trial 3
```

For each trial, the following are measured:

- raw rows sampled
- number of distinct values
- number of histogram buckets
- histogram construction time
- optimal objective value
- maximum selectivity error
- value at which the maximum error occurs

The three trial results are saved in:

```text
results/id_trials_1000.csv
results/id_trials_3000.csv
results/id_trials_5000.csv

results/title_trials_1000.csv
results/title_trials_3000.csv
results/title_trials_5000.csv
```

### Averaging

For each sample size, the final `experiment_results.csv` uses the arithmetic mean of the three trials for:

```text
build_time_seconds
max_selectivity_error
optimal_objective
```

The number of trials is recorded in:

```text
num_trials
```

and is equal to:

```text
3
```

The per-trial CSV files are retained so that the averages can be independently verified.

## 7. Optimal Serial Histogram

The histogram contains:

```text
20 buckets
```

over an ordered set of distinct values.

For each distinct value:

```text
Value       Frequency
A           5
B           2
C           8
D           4
...
```

The ordered domain is partitioned into contiguous buckets.

For bucket `i`:

```text
n_i = number of distinct values in the bucket
V_i = variance of frequencies in the bucket
```

The objective minimized by the dynamic-programming algorithm is:

```text
Σ(n_i × V_i)
```

Equivalently, for a bucket:

```text
n × variance
= Σ(f²) - (Σf)² / n
```

Prefix sums are used to calculate bucket costs efficiently.

The dynamic-programming algorithm then finds the partition into the requested number of contiguous buckets with minimum total cost.

## 8. Selectivity Error

For a value whose actual frequency is `f`, the histogram estimates its frequency using the average frequency of the bucket containing that value.

The selectivity error is:

```text
|estimated_frequency - actual_frequency| / sample_rows
```

The maximum error among the sampled values is recorded for each trial.

The per-value errors from the representative first trial are saved in:

```text
results/id_errors_1000.csv
results/id_errors_3000.csv
results/id_errors_5000.csv

results/title_errors_1000.csv
results/title_errors_3000.csv
results/title_errors_5000.csv
```

The final experiment summary reports the **average of the maximum selectivity error across the three trials** for each column and sample size.

## 12. Full-Table Time Extrapolation

The program estimates the time required to construct the histogram for the full table.

The measured construction times for the three sample sizes are fitted using:

```text
T(n) = slope × n + intercept
```

where:

```text
n = sample size / number of rows processed
T(n) = histogram construction time
```

The extrapolated result is stored in:

```text
results/full_table_extrapolation.csv
```

The known full-table cardinality used by the experiment is:

```text
2,528,312 rows
```

The actual database `COUNT(*)` is also checked and a warning is printed if it differs from the specified cardinality.

## 16. Important Notes

- The experiment uses **20 buckets**.
- Sample sizes are **1,000, 3,000, and 5,000**.
- Both `id` and `title` are evaluated.
- Three independent trials are executed for every column/sample-size combination.
- Final build time and maximum selectivity error are averaged over the three trials.
- Row-count checks are performed for every sampled dataset.
- For `title`, the nominal sample size refers to the number of **distinct titles**, while duplicate rows are retained for frequency calculation.
- Boundary/error/metadata files and representative histogram plots are based on trial 1.
- Per-trial CSV files contain all three trials and allow the reported averages to be verified.
- `plot_histogram.py` and `plot.py` visualize already-generated histogram data; they do not recompute the optimal histogram.
- The database password should be replaced with an appropriate local value before sharing the project.
- Existing files in `results/` are generated artifacts and can be regenerated by running `run.bat`.

## 17. Summary

The project provides an empirical investigation of histogram construction using PostgreSQL and an optimal serial histogram implementation.

It studies:

- PostgreSQL's built-in histogram statistics
- The effect of sample size on construction time
- The effect of sample size on selectivity error
- The effect of data distribution on optimal bucket boundaries
- The difference between raw-row count and distinct-value count for duplicated text data
- Trial-to-trial variation through three independent experiments
- Full-table construction-time extrapolation

The main implementation is contained in `code/histogram.py`, while generated experimental data and visualizations are stored in `results/`.
